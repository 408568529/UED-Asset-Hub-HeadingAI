# UED Asset Hub · 比赛源码

UED Asset Hub 是面向设计团队的设计资产与知识协作平台。它将分散的设计资料、工作规范与 AI 能力放在一个工作空间中，方便查找、复用和协作。

- **知识库与设计资产**：集中整理和浏览设计资料，让团队经验可以持续积累与复用。
- **微规范与 Haldur Skill 工作台**：管理可复用的设计规范和技能资料，为设计工作提供统一参考。
- **Agent 与 Knowledge MCP**：通过对话使用 AI，并让 Agent 读取平台知识，辅助查询和完成任务。AI 问答需要先配置可用的模型。
- **GenUI**：在对话中生成和预览交互组件，支持组件操作及状态回读。

平台采用程序与数据分离的方式部署；管理员负责初始化实例、设置模型及管理内容。

本仓库分发开发源码，不包含运行 DATA、真实会话、模型密钥或 Windows 已安装运行目录。Windows 完整交付文件夹由此源码另行构建，不等同于源码目录。

## Windows 完整交付包：首次部署与启动

以下步骤适用于**已经构建好的 Windows 完整交付文件夹**。从 Git 下载的本仓库是开发源码，根目录没有可直接运行的 02；开发者构建说明见后文。

1. **放好完整交付文件夹。** 保留包内的全部文件与目录，不要只复制启动文件。后续资料存储在你选择的外部数据目录中。
2. **右键 `02-轻点击我启动.cmd`，选择“以管理员身份运行”。** 在 Windows 确认框中允许本次启动。此路径用于满足完整包运行所需的文件链接权限；不需要安装 MSVC，也不需要手动修改系统 PATH 或安全策略。正常使用直接运行 02，无需先运行 01；01 仅供独立排障，不要与 02 同时运行。
3. **等待环境预检完成。** 启动中心会检查运行环境，并核对全部构件与 SHA-256。**这一步会比较慢，可能持续数分钟；本轮实机记录中曾接近 20 分钟，具体取决于磁盘和机器环境。** 校验期间可能长时间没有中间进度，请保持页面与启动窗口开启，不要反复点击 01、02 或“重新检查”。等待所有必需检查项均显示绿色 `PASS` 后，再继续配置；如出现红色 `FAIL`，请先根据提示处理，不要跳过检查。
4. **选择文件存储路径并设置管理员。** 在“数据目录与管理员”中点击“选择父目录”，程序会填入其下新的 `UED-Asset-Hub-Data` 子目录路径。可修改子目录名称，但新建实例的目标必须尚不存在，**不要提前手动创建这个子目录**。填写管理员账号、至少 12 位的密码及确认密码，勾选新建实例确认，再点击“确认新建并设置管理员”，等待初始化完成。

   **请在提交前自行保存管理员账号和密码，建议使用密码管理器。** 本平台没有默认管理员密码；初始化后，启动中心不会再次展示密码，也不会提供明文找回入口。后续登录管理页面和模型设置时仍会用到这组账号密码。不要把密码放进公开源码、截图或问题反馈中。

5. **保留默认“本机模式”，点击“启动 UED Asset Hub”。** 按钮会进入 loading 并显示“正在启动，成功后打开浏览器”。**请等待按钮加载结束、服务就绪后自动打开首页，不要在等待期间重复点击或关闭启动窗口。** 启动过程可能再次核验构件，也可能需要较长时间；如果最终显示错误，请保留错误文字供排查。若服务已就绪但浏览器未自动打开，可点击“在浏览器打开 UED Asset Hub”，或复制页面给出的地址到浏览器地址栏访问。
6. **进入首页后使用平台。** 默认本机地址为 `http://127.0.0.1:3247/`，仅本机可访问。需要 AI 问答时，从 Agent 设置进入模型设置，用刚才保存的管理员账号登录后填写自己的模型配置。模型密钥不随交付包提供，也无需在启动中心填写。

### 后续启动与停止

- 再次使用时，以管理员身份运行同一个文件夹中的 02，等待检查和启动完成；已配置的实例会沿用原数据目录与管理员配置，无需重复新建。
- 停止时使用启动中心的“停止本安装”，或运行 `03-停止运行.cmd`。关闭浏览器页面不会停止后台服务。
- 请保留并妥善备份外部数据目录；其中包含业务资料、会话及敏感配置。不要把已有数据目录当成新实例初始化，也不要随程序目录一起误删。
- 上述流程介绍本机运行。局域网共享需要额外的 HTTPS 与访问配置，请参阅[完整运行说明](docs/v2.5/README.md)，不要直接开放本机端口。

## 开发者：源码安装与构建

固定依赖以 package-lock.json 为准。已核验的交付运行工具为 Node 22.23.2 / npm 10.9.8；Next.js 锁定版本为 15.5.27。请使用受支持的原生平台版本。

```bash
npm ci
npm run build
```

前端开发可复制 .env.example 为 .env.local，再设置本环境的管理员凭据和独立存储目录，运行 npm run dev。该命令只启动前端，不能替代完整 Agent 运行验收。不要将个人 .env 文件或已有 DATA 提交到 Git。

完整 Hub / Agent 运行由 npm run start:host 管理，需要按固定契约准备 DSH 0.1.1-rc.2、GenUI 0.15.1 和各自独立运行目录，见 [固定依赖](docs/v2.5/DEPENDENCIES.md)、[构建资源](docs/v2.5/BUILD-RESOURCES.md) 与 [运行说明](docs/v2.5/README.md)。模型密钥由管理员在隔离实例设置页输入，不随源码或 Windows 程序交付。

三个 Windows 原生辅助程序的 C++ 源码和构建脚本均保留。开发者从源码编译它们需要合适的独立 Windows 工具链；最终 Windows 用户使用已构建完整文件夹，无需因辅助程序安装 MSVC。来源和兼容性不能确认的二进制不得纳入交付。
